# Resume-Kit-2 Alignment Audit — 2026-08-13

Scope: full codebase vs `PRODUCT_VISION_AND_CONTRACTS.md`, `PROJECT_STRUCTURE_AND_TEST_STRATEGY.md`, `IMPLEMENTATION_PLAN.md`, `CONTRACT_SURFACE_ALIGNMENT.md`, `SMOKE_TEST.md`, `E2E_TEST.md`; all 49 Metis initiatives, 5 ADRs, vision, and strategy; all remaining markdown/packaging files. 18 review agents + orchestrator spot-verification; all empirical claims below were verified by executing code, not by reading docs.

---

## 1. Executive Summary

**All executable gates are green — and green is misleading.** The PR gate (188 contract/boundary/guardrail tests), smoke gate, and future-contract gate all pass. But the test suite is fixture-tuned and in several places vacuous, so it certifies implementations that are 25–55% of product depth and, in a few load-bearing places, actively broken or gamed.

**The Metis planning layer is systematically stale and template-hollow.** All 49 initiatives were generated the same day the ~7,500-line implementation wave landed. Every one still describes the package as a passing "scaffold," every one has a three-bullet noun-phrase "Detailed Design" byte-identical across its siblings, none names the real defects the code now contains, and every `blocked_by` frontmatter is `[]` while dependency chains exist only in prose — so Metis tooling sees 49 unblocked, indistinguishable initiatives.

**Verdict distribution:** 47 of 49 initiatives = `incomplete`, 2 = `misaligned` (RKIT-I-0045, RKIT-I-0047), 0 = `aligned`. All 5 ADRs = `minor_issues`. None of this is misdirected scope — no initiative plans behavior in the wrong package — the failures are completeness, staleness, ordering, and coverage gaps.

## 3. Critical Cross-Cutting Findings

1. **The honesty gates are lookup tables, not gates.** `_GUARDED_TERMS` hardcodes exactly the five fixture claims (aws, graphql, staff, "20 million", "30 engineers"). Verified: "Served 50 million users daily", "Principal Engineer leading 100 people", "Kubernetes expert" all validate with zero grounding. Title guard covers only the word "staff". The same pattern repeats in career-store (5-title list, bare-digit years parser that flags "React 18" vs "React 17" as a years conflict) and resume-cli (`_prohibited_additions` hardcodes the doc's example strings).

2. **The legitimate tailoring path is broken end-to-end.** `validateFinalResume` calls grounding with `applied_operations=[]` hardcoded, so a correctly validated-and-applied AWS addition *fails* final validation as an unsupported claim. The one path the product exists to support does not work through the official surface.

3. **Truth-escalation bypasses in career-store.** `verifyFact` promotes inferred→user_verified when the answer merely *contains* substrings like "yes"/"correct" — "incorrect" and "yesterday I did nothing" both count as confirmation (verified). inferred→source_stated escalation is completely ungated. A merely-`related` Azure→AWS relationship makes Azure resolve an AWS requirement as `exact_match` even with `allow_related_as_equivalent=False` — the exact misalignment example CONTRACT_SURFACE_ALIGNMENT.md names — and the contract test that should catch it asserts only the absence of a string (`equivalent_match`) no code path produces.

4. **DTO/enum drift is institutionalized by the passing test suite.** VerificationState drops contract-valid `imported`, adds `explicitly_missing`/`conflicted`; ResolutionState drops `not_applicable`, adds `conflicted`; ChangeOperation lacks verbs rewrite/insert/move, statuses accepted/modified, and the mandatory `reason` + `provenance` fields; MatchResult lacks threshold/decision/dimensions/hardRequirementsResolved. `tests/contract/test_shared_dto_schemas_contract.py:45-62` hard-asserts the drifted sets, and IMPLEMENTATION_PLAN forbids editing tests — so the drift is locked in and **no ADR or initiative authorizes resolving it in either direction**.

5. **The §13 configuration contract is entirely unwired.** Every documented key (`matching.scoreAutoThreshold`, `matching.weights`, `requireHardRequirementsResolved`, `resume.*`, `guardrails.*`) is ignored in favor of ad-hoc flat keys. Verified: `requireHardRequirementsResolved: true` does not gate continuation with an unresolved required requirement. No initiative owns this; no ADR decides which vocabulary wins.

6. **Workflow checkpoints are dead code in the product path.** resume-cli imports only `createRun`/`buildRunManifest`/`CHECKPOINT_ORDER` and never calls advance/next/record/recover/assertCanComplete; `resume run` echoes the full checkpoint list as if traversed. Additionally: run IDs are config-hash-only (two same-config runs collide and overwrite each other's state — breaks Job A/Job B auditing), blocked-transition audit events are never persisted, and the RESOLVE_GAPS→MATCH_BASE loop never terminates once a fact is verified, making BUILD_SELECTION_PLAN→COMPLETE unreachable (all verified by execution).

7. **Test-fidelity gaps let two packages ship against imaginary interfaces.** career-mcp's 19 contract tests run against a FakeCareerStore exposing a snake_case API the real store doesn't have — the production code path is nearly untested and demonstrably fails (advertised 'imported'/'child'/'parent' rejected at runtime, types filter is a no-op, find_matches emits duplicate contradictory rows). resume-plugin's presenters read field names invented by its own surface file — fed real CLI output, reports/audits render as empty lists.

8. **The release-blocking strategy is roughly half paper.** No E2E runner, no Job B persistent-learning test (mandatory, release-blocking), no duplicate-question test, no migration fixtures/checker, snapshot files contain prose sentences instead of comparable data, `--future-contract` is a vestigial alias of the PR gate (identical module lists), and the "E2E release-candidate gate" CI job contains no E2E.

## 4. Metis Audit

### 4.1 Systemic (applies to all 49 initiatives)
- **Stale baseline:** every doc claims "Current contracts and guardrails pass for the scaffold." The packages are 25–55% implemented with specific verified defects. Decomposing from these docs would re-plan finished work and miss every actual defect.
- **Template hollowness:** within each package group, Goals/Non-Goals, Requirements, Detailed Design, Testing Strategy, Alternatives, and Implementation Plan are byte-identical boilerplate; only the one-sentence Outcome differs. Scope boundaries between siblings exist only in titles. This violates the required Metis completeness bar (no stubs, every section substantive).
- **Broken dependency metadata:** every initiative's `blocked_by` is `[]`; chains exist only as prose titles. Undeclared transitive ADR blockers are pervasive (details below). `estimated_complexity: M` uniformly, which is not credible (RKIT-I-0009 is already done; RKIT-I-0014 is the largest item in its package).
- **Frontmatter hygiene:** duplicated tags (`#initiative`/`#phase/...` twice) and literal `NULL` linkage fields in every generated doc.

## 6. Recommended Sequence

1. **Decide the drift ADRs first** (new ADRs: DTO/enum vocabulary, §13 config vocabulary, plus the smaller ones above). Every package and the shared-DTO contract test are waiting on these; until decided, tests lock the drift in and no initiative can decompose cleanly.
2. **Fix the two-line-class critical defects** that break the product's core promise regardless of planning: `validateFinalResume` applied-operations hole, career-store confirmation substring bug + related→exact term pollution, run-ID collision, RESOLVE_GAPS termination. Each needs a contract-test strengthening in the same change (with explicit permission, since tests are protected).
3. **Re-baseline the Metis layer before any decomposition:** rewrite each initiative's Context/current-state with the done vs fixture-tuned vs missing delta (this audit provides the per-package lists), replace boilerplate Detailed Designs with the known-defect and gap lists, encode real `blocked_by` (including transitive ADR blocks), break the artificial serializations, add the missing coverage initiatives (§4.5 list), and split/rescope where flagged (close I-0009, split ADR-0003, consolidate the plugin group).
4. **Fix the doc bugs** (worker command, section numbers, canonical-command ambiguity, §3 MVP-layout sentence, SMOKE fixture reconciliation) — cheap, and they actively mislead implementing agents today.
5. **Only then** decompose to tasks, in the existing build order, with the strengthened specs as the gate.

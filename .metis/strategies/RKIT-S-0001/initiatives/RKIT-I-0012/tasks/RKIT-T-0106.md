# Policy module, call_tool confirmation enforcement, confirmed arg, computed flags, context honesty

## Parent Initiative

[[RKIT-I-0012]]

## Objective

Make career-mcp confirmation enforcement REAL per initiative R1–R4: a pure policy evaluation step gating every store mutation (unconfirmed required-confirmation mutation → typed `policy_error`, zero store calls), a defined `confirmed: true` satisfaction contract on mutating tool schemas, `get_unverified`'s `confirmation_required` computed from policy instead of hardcoded true, and honest `context` semantics (feed policy or remove the echo).

## Acceptance Criteria

## Acceptance Criteria

- [ ] New module `career-mcp/career_mcp/policy.py`: pure `evaluate_policy(tool, arguments, confirmed) -> PolicyDecision {allowed, requires_confirmation, reason}`; capability classification covers ALL tools in the canonical manifest (read tools always allowed; mutating tools — propose_fact, verify_fact, add_evidence, add_relationship, and any other mutating surfaces the manifest declares (check MUTATING classification already used by the audit envelope / career_store_guardrails) — require host-mediated confirmation). No principals/scopes/roles anywhere (RKIT-A-0002 item 2 — by decision, not omission; a code comment states this).
- [ ] `call_tool` evaluates policy AFTER validation, BEFORE store dispatch: unconfirmed required mutation returns status `rejected`, `error.type = policy_error`, reason `confirmation_required` (rides the existing I-0010 envelope helper `_tool_result`), and provably makes ZERO store calls (contract test with a store spy). Confirmed calls proceed and the result exposes `confirmation_required: true, confirmed: true` (the values RKIT-I-0013's audit events will record).
- [ ] `confirmed` boolean argument added to every mutating tool's schema in the CANONICAL manifest `career-mcp/career_mcp/tool_surface.json`, with the generated byte-copy `career-mcp/tool_surface.json` regenerated via `career-mcp/tools/sync_tool_surface.py` (the protected career_mcp_guardrails asserts copy identity — regenerate, don't hand-edit). TOOL_ARGUMENTS consumed-arguments assertion (from I-0010) must cover `confirmed` so it can't silently drop.
- [ ] `get_unverified`'s per-fact `confirmation_required` (the hardcoded `True` near career_mcp/__init__.py:611) computed from `evaluate_policy` for verifying that fact — contract test shows the flag varies with policy rather than being constant.
- [ ] `context` honesty (R4): the pure echo at call_tool (`result.setdefault("context", context)` ~:125) is ELIMINATED — either context feeds `evaluate_policy` with defined semantics (document exactly what fields do) or the parameter is removed from schemas and call paths entirely. Pick the simpler honest option and justify in the report; no half-measure.
- [ ] Read tools unaffected (contract test); existing 8-tool real-store contract tier stays green unmodified or strengthened-only.
- [ ] career-mcp/TEST_SPEC.md (NOT protected) gains confirmation-enforcement items naming covering tests.
- [ ] Gates green: `--pr`, `--smoke`, `--future-contract`. NO protected edits (tools/career_mcp_guardrails.py is protected; the canonical-manifest + sync-copy route avoids it — verify the guardrail's expectations before finalizing schema changes).

## Implementation Notes

### Technical Approach
Policy is MCP-owned, store keeps state-transition authority (gate BEFORE dispatch, never weaken store checks). resume-cli orchestration currently calling mutating tools without `confirmed` will start getting policy_error — check smoke/CLI paths and update the CALLERS to pass explicit confirmation (that is the intended product behavior), never soften the gate to keep smoke green.

### Dependencies
I-0010 envelope (landed), I-0011 STORE_METHOD_BY_TOOL mapping (landed) — reuse their classification/validation seams.

### Risk Considerations
career_mcp_guardrails.py (protected) pins manifest properties — read it first; if adding `confirmed` to schemas trips a pinned expectation, STOP and defer per discipline rather than ending red. Smoke drives real CLI flows — expect caller updates.

Recommended Agent: opus + high
